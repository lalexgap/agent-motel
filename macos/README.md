# Agent Motel for macOS

A small AppKit app for watching an Agent Motel fleet: a sidebar of agents with live status, each agent's chat, a composer to send it a message, and an interactive terminal on the agent's pane. The page is bundled inside the app and served from `am-app://app/`; all server traffic goes through a native bridge that holds the access token. Requires macOS 12.3 or later.

Every request the app can send other than a `GET` is one of these, each a separate bridge method that takes values and builds its own path and body (`:key` is the agent, `name` or `host:name`):

- **Messages:** send a message (`POST /api/agents/:key/messages` with `{text, mode}`, `mode` being `queue` or `now`) and cancel one that is still queued (`DELETE /api/agents/:key/messages/:id`). A message is still typed input: its text can be anything you could type at the agent's prompt, including a slash command such as `/exit`.
- **Lifecycle:** resume (`POST …/resume`), and, after a native confirmation, restart, interrupt (Esc only, never with text), stop (`POST …/restart`, `…/interrupt`, `…/stop`, each with `{}`) and remove (`DELETE /api/agents/:key`; the worktree is kept).
- **Manage:** rename (`POST …/rename` with `{name}`); after confirmation, move to or from a configured remote host (`POST …/move` with `{host, dir?}`) and change the model (`POST …/model` with `{model, effort?, createdAt, status}`, which restarts the agent); hand over to the other provider (`POST …/handoff` with `{to, newName?, full?}`).
- **Create:** a new agent (`POST /api/agents` with `{name, task, provider, dir? or remoteDir?, host?, model?, effort?, role?}`; never `inPlace` or `codex`) and start or revive the concierge (`POST /api/concierge`).
- **Answer:** a relay permission request (`POST …/permissions/:id` with `{optionId}`) and a Claude pane prompt (`POST …/prompt` with `{id, optionId, text?}`).
- **Attach:** upload an image (`POST …/files` with the raw bytes: PNG, JPEG, GIF or WebP, at most 10 MiB).
- **Search:** conversations (`POST /api/search` with `{query}`; read-only on the server).
- **Decisions:** answer or withdraw local decisions through the narrow native `decisions.answer` bridge (`POST /api/decisions/answer` with bounded values). Older servers fall back to `POST /api/decisions/link`; that secret HTTPS capability is validated and opened natively, never returned to the bundled page.

There is no generic write method: interrupt with text, `interrupt` send mode and every other route stay unreachable. The interactive terminal is separate (see [Terminal](#terminal)): its own four bridge methods, which carry terminal messages, never URLs or raw frames.

## Build

Run `bash macos/build.sh` on a Mac with Xcode Command Line Tools and [Bun](https://bun.sh). It runs the unit tests (navigation policy, connection URL policy, API path validation, message and action validation and request shape, terminal validation, request shape, cookie parsing, error mapping and output coalescing, SSE parser, bundle file resolution), builds the frontend with `bun desktop/build.ts`, copies `desktop/dist` into `Contents/Resources/web`, and produces `macos/build/Agent Motel.app` plus a zip for the build machine's architecture. Set `WEB_DIST` (relative to `macos/`, or absolute) to use an already built frontend instead. Copy the app into `~/Applications` and open it.

## First run

The app opens on the connection form. Enter a name, the server URL (for example `https://am.example.com` or `http://127.0.0.1:8790`) and the access token (`am token` on the server). The app checks `/api/health` with the token before saving. **⌘,** reopens the connection list.

## Security model

- The token is stored in the login Keychain as a generic password (service = the bundle identifier, account = the connection id). It is sent only as an `Authorization: Bearer` header, never logged, never put in a URL, and never returned to the page, which only sees `hasToken`. Changing a connection's URL requires entering the token again.
- The page has no network access: its Content Security Policy sets `connect-src 'none'`, and only bundled scripts run. Every request goes through the bridge, which accepts messages only from the app page's main frame, validates every parameter, and builds request URLs from the saved server plus an `/api/...` path, so the page cannot redirect a request to another host.
- `api.get` only ever sends `GET`. The write methods take values, not paths, and `MessagePolicy.swift` is the only code that can build a non-`GET` request. Agents are `name` or `host:name`, checked against am's name rules and percent-encoded into one path segment; new names and roles follow the same rule and may not be `concierge`; enums (provider, status, handover target, image type) are closed lists; free text has a UTF-8 byte limit and no control characters other than tab and line breaks (none at all in single-line values), since am types some of it into the agent's pane where Esc or Ctrl-C would act on the agent. Bodies contain exactly the listed keys. Message text, tasks and search queries are trimmed; images arrive as base64, are decoded once in the app, size-checked and matched against the image type's signature before upload, and are never logged.
- **Native confirmation.** Restart, interrupt, stop, remove, move and model changes are only sent after you accept an `NSAlert` sheet on the app window, raised by the app itself. The page cannot skip, answer or restyle it. The sheet names the agent and the server and shows the agent's current status; Cancel or Esc sends nothing. For remove, Cancel is the default button and Remove is styled as destructive. One confirmation at a time: a second one while a sheet is open is refused. A sheet cannot be accepted unread from the keyboard: for half a second after it appears, and again each time it becomes the key window (switching back to the app, say), the app swallows every key but Esc (in a native event monitor, before AppKit's own key handling), and a repeated (held) Return, Enter or Space never counts, so a Return already on its way (even one aimed at the main window) or a held Enter does nothing, and a click on the sheet in its first half second is ignored too. If the app is not active when a confirmation is needed it does not come to the front: the sheet is attached to its window in the background and the Dock icon bounces once, so typing in another app cannot land on it, and a Return typed right after switching back to the app does nothing. The terminal consent sheet (below) follows the same rules.
- **Existence pre-check.** Before showing the sheet, the app reads the agent's exact-name detail (`GET /api/agents/:key`). If the agent no longer exists the call fails without a sheet ("This agent no longer exists"); after the user accepts, the lookup is repeated just before sending, so an agent removed while the sheet was open is not acted on. This matters because am's `stop` also matches old names and unique prefixes, so a stale name could otherwise stop a different agent.
- No write is ever retried: after a network failure or timeout the call fails and the outcome is unknown. Timeouts are per method: 30 seconds for search, 45 for answering prompts, 60 for messages and lifecycle actions, 120 for model changes, uploads and the concierge, 150 for handover and create, and 600 for a move. A long move does not hold up other calls, and quitting the app cancels it.
- Requests use an ephemeral session (no cookies, cache or credential storage), time out after 30 seconds (writes as above), cap responses at 32 MiB and refuse redirects so the token is never replayed elsewhere.
- Plain `http` is accepted only for localhost, `127.0.0.0/8`, `[::1]`, Tailscale addresses (`100.64.0.0/10`) and `*.ts.net`; anything else must use `https`. URLs with a user name or password are rejected.
- The app is sandboxed with outbound network access only. Only `am-app://app/` pages load in the window; clicked `http(s)` links open in the default browser.

## Terminal

An agent's Terminal tab attaches to its tmux pane, like the browser UI's terminal: what you type goes straight to the agent, including Ctrl-C and shell commands. That is the same authority as ssh to the machine, far more than the message bridge, so it is gated separately.

- **Web origin.** The server only allows terminals from its configured web origin (`webOrigin`), so the connection's URL must be exactly that address (for example `https://am.example.com`). On a loopback or tunnel URL, or a server without `webOrigin`, opening a terminal fails with a plain explanation. The app sends `Origin: <connection URL>` on these requests. Terminals refuse plain `http`, Tailscale addresses included, except to `127.0.0.0/8`, `localhost` and `[::1]` (the fixture): the session cookie must never travel in clear text.
- **Session.** The terminal route refuses the bearer token by design and needs a browser session. On the first terminal for a connection the app signs in (`POST /auth/login` with the token) and keeps the `__Host-am_session` cookie in memory only: never stored, never logged, never returned to the page or put in an event. The login, the preflight (`GET /api/agents/:key/terminal`) and the WebSocket upgrade on the same path are the only requests that carry it; they are built in one file (`TerminalPolicy.swift`) by a type nothing else can construct, without a bearer header, with Foundation's cookie handling off and redirects refused. `api.get` still cannot reach `/auth/*`. A 401 from the preflight or the upgrade (a server restart forgets sessions) signs in once more and retries that step once; a session revoked on an open terminal (close code 4001) closes it and the next open signs in afresh. The server's sessions last 12 hours and it allows 10 sign-ins a minute. Removing a connection, changing its URL or token, or quitting drops the session.
- **Consent.** The first terminal on a connection in each app run asks natively: "Open interactive terminals on <connection>?" with Allow and Cancel and a "Don't ask again for this server" checkbox. The checkbox is remembered per connection id and URL, and forgotten when the URL changes or the connection is removed. The page cannot answer, skip or pre-set it.
- **Limits.** At most 4 terminals at once. Input is forwarded in order, never merged or retried, at most 16 KiB per message. Output is batched for the page (up to 16 ms or 64 KiB per event); if more than 4 MiB is waiting for the page, the terminal closes ("Output exceeded rendering capacity") and can be reconnected. The app pings every 30 seconds so an idle terminal outlives the server's 2-minute idle timeout. Reloading the page closes its terminals; closing one never stops the agent.

## Shortcuts

**⌘,** connections, **⌘R** refresh (reloads the page if it never finished loading), **⌘F** find, **⌘1** show the agent's chat, **⌘2** show its terminal, **⌘0** show the window, **⌘W** close it, **⌘M** minimise. Closing the window or quitting leaves server agents running. Set `AM_DEBUG=1` in the environment to enable the Web Inspector. If the page fails to load, a Reload button appears.

## Smoke test

`bash macos/smoke.sh` is an opt-in integration check on a Mac with a logged-in desktop session. It builds the app under a separate bundle id (`ca.alexgap.agent-motel.smoke`, with its own defaults and Keychain items), starts the synthetic fixture server (`bun desktop/fixtures/server.ts --port 8791`) and launches the app in the background without activating it. It saves a connection through the real bridge, checks `/api/health`, a wrong token, rejected API paths, the page's blocked network access and the event stream, rejects invalid messages, sends and cancels a queued message and sends a `now` message, rejects invalid writes, cancels and accepts each confirmation sheet by clicking its buttons (or pressing Esc) in the background window without activating the app, sends every other write once, checks that the fixture's log of received requests holds exactly what was sent, opens an agent's chat, sends from the composer, queues and cancels a message there, writes a screenshot (`SMOKE_SCREENSHOT`, default in the temp directory), then removes the connection and its Keychain item. It checks that a Return posted as a confirmation sheet appears, and a repeated Return, do not accept it while a fresh Return after the delay does. Terminal checks use the fixture's sign-in and fake shell: rejections, the consent sheet (Cancel sends nothing; Allow signs in, preflights and upgrades once), typing and resizing, the 4-terminal limit, close, a forced 4001, a forgotten session, an 8 MiB flood, and a scan of every result and event for the session cookie; the UI step opens the Terminal tab and types through xterm. The app is then launched a second time to check that "Don't ask again" survived and is cleared by removing the connection. The write checks need the fixture server (its `/__fixture/requests` log, `/__fixture/reset` and its agents); `smoke.sh` refuses a `SMOKE_URL` that is not on loopback, because the smoke test stops, removes and creates agents. `SMOKE_BRIDGE_ONLY=1` skips the UI steps.

## Signing

Builds use local ad-hoc signing by default. An ad-hoc signature changes with every build, so macOS may ask again for Keychain access to a saved token after you rebuild. Run `bash macos/setup-signing.sh` once to avoid that: it creates a self-signed identity, "Agent Motel Local Signing", in its own keychain (`~/Library/Keychains/agent-motel-signing.keychain-db`), and `build.sh` signs with it whenever that keychain exists. Gatekeeper does not trust it.

The trade-off: the identity's keychain password is in this repository, so any process running as you can sign its own binary with this identity, and that binary passes the Keychain check for saved tokens without a prompt. Setting it up removes the Keychain prompt that otherwise guards your tokens. If that matters, skip `setup-signing.sh` and accept the prompt after every rebuild.

For distribution to other Macs, set `SIGNING_IDENTITY` to your Developer ID Application certificate and notarize the zip with Apple's `notarytool`, then staple the app and repackage it. This repository does not include signing credentials or claim notarized distribution. No automatic updater is included.
